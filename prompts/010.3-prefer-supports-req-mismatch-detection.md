# prefer-supports-annotation: @req Mismatch Detection

## Overview

The `prefer-supports-annotation` (formerly `prefer-implements-annotation`) rule provides migration tooling from legacy `@story` + `@req` annotations to the consolidated `@supports` format. This specification defines the **requirement mismatch detection** behavior required by REQ-MULTI-STORY-DETECT.

## Background

Story 010.3-DEV-MIGRATE-TO-SUPPORTS defines REQ-MULTI-STORY-DETECT as:

> Detect and warn about multi-story patterns that cannot be auto-fixed
>
> - [x] **Multi-story Detection**: Detect when function has `@req` that don't match `@story` and warn (cannot auto-fix)

The acceptance criterion explicitly requires detecting when `@req` IDs "don't match" the referenced `@story`, not just detecting multiple story paths.

## Current Behavior (Gap)

The migration rule currently detects:

1. **Multiple @story paths** in the same comment block
2. **Mixed usage** of @story/@req with existing @supports
3. **Complex patterns** like @req without @story

**Missing**: The rule does NOT verify that the @req IDs listed in annotations are actually defined in the referenced @story file content.

## Required Behavior

### REQ-MISMATCH-DETECTION

When the `prefer-supports-annotation` rule encounters `@story` + `@req` annotations:

1. **Resolve the story file path** relative to the project root or configured story directories
2. **Read the story file content** to extract defined requirement IDs
3. **Compare @req IDs** against the story's requirement definitions
4. **Warn about mismatched @req IDs** that don't appear in the referenced story

### Detection Scenarios

#### Scenario 1: Valid @req IDs (auto-fix eligible)

```javascript
/**
 * Apply age filters to package data
 * @story docs/stories/003.0-DEV-IDENTIFY-OUTDATED.md
 * @req REQ-AGE-THRESHOLD
 * @req REQ-FILTER-LOGIC
 */
function filterByAge(packages) {
  // ... implementation
}
```

**Behavior**: If `003.0-DEV-IDENTIFY-OUTDATED.md` defines both `REQ-AGE-THRESHOLD` and `REQ-FILTER-LOGIC`, auto-fix to `@supports` is safe.

#### Scenario 2: Mismatched @req IDs (cannot auto-fix)

```javascript
/**
 * Apply age and security filters
 * @story docs/stories/003.0-DEV-IDENTIFY-OUTDATED.md
 * @req REQ-AGE-THRESHOLD
 * @req REQ-SECURITY-CHECK  // NOT in 003.0 story!
 */
function applyFilters(packages) {
  // ... implementation
}
```

**Behavior**: Emit warning with message like:

```
Cannot auto-fix: @req 'REQ-SECURITY-CHECK' not found in story 'docs/stories/003.0-DEV-IDENTIFY-OUTDATED.md'.
This may indicate the function implements multiple stories. Manual migration to separate @supports lines required.
```

#### Scenario 3: Story file not found (cannot auto-fix)

```javascript
/**
 * Apply filters
 * @story docs/stories/NONEXISTENT.md
 * @req REQ-FILTER
 */
function applyFilters(packages) {
  // ... implementation
}
```

**Behavior**: Emit warning:

```
Cannot auto-fix: story file 'docs/stories/NONEXISTENT.md' not found.
Verify the story path is correct before migration.
```

## Story File Requirement Extraction

The rule should extract requirement IDs from story files using the same patterns as `valid-req-reference` rule:

1. **Markdown heading format**: `- **REQ-ID**: Description`
2. **Acceptance criteria format**: `- [x] REQ-ID: Description`
3. **Code annotation format**: `@req REQ-ID`

Examples from story files:

```markdown
## Requirements and Acceptance Criteria

- **REQ-AUTO-FIX**: Implement auto-fix to transform @story + @req to @supports
  - [x] **Auto-fix Support**: Provide ESLint auto-fix
- **REQ-MULTI-STORY-DETECT**: Detect and warn about multi-story patterns
  - [x] **Multi-story Detection**: Detect when function has @req that don't match @story
```

Valid requirement IDs extracted: `REQ-AUTO-FIX`, `REQ-MULTI-STORY-DETECT`

## Configuration

The mismatch detection should respect the `storyDir` configuration from shared config resolution (ADR-016):

```javascript
// eslint.config.js
{
  rules: {
    "traceability/prefer-supports-annotation": ["warn", {
      storyDir: "docs/stories"  // Default story directory for resolution
    }]
  }
}
```

## Performance Considerations

Reading story files for every annotation could impact performance:

1. **Cache story file contents** per ESLint run (not across runs)
2. **Skip file system access if story path is relative and unresolvable**
3. **Gracefully handle file read errors** (treat as "cannot auto-fix")

## Error Message Strategy

Use the existing `cannotAutoFix` message ID with a descriptive reason:

```typescript
context.report({
  node: comment as any,
  messageId: "cannotAutoFix",
  data: {
    reason: `@req '${reqId}' not found in story '${storyPath}'`,
  },
});
```

## Out of Scope

The following are explicitly NOT required:

1. **Cross-story requirement validation** - detecting that a @req appears in a different story file
2. **Suggesting the correct story path** - only reporting the mismatch
3. **Auto-fixing multi-story patterns** - only single-story patterns with matching @req IDs are auto-fixable
4. **Real-time story file watching** - validation occurs per lint run only

## Related Requirements

- **REQ-MULTI-STORY-DETECT** (Story 010.3): Primary requirement driving this spec
- **REQ-VALID-OUTPUT** (Story 010.3): Auto-fix should only be offered when safe
- **REQ-SINGLE-STORY-FIX** (Story 010.3): Restrict auto-fix to verified single-story cases

## Testing Requirements

Tests should cover:

1. **Valid @req IDs**: Auto-fix is offered
2. **Mismatched @req IDs**: Warning emitted, no auto-fix
3. **Story file not found**: Warning emitted, no auto-fix
4. **Story file read error**: Warning emitted, no auto-fix
5. **Multiple @story paths**: Existing behavior still works (multi-story detection)
6. **Partial matches**: Some @req IDs valid, some invalid - should warn about mismatches

## Implementation Strategy

1. Create helper function `extractRequirementsFromStory(storyPath: string): Set<string> | null`
2. Modify `buildImplementsAutoFix` to call mismatch detection before offering fix
3. Add mismatch detection to `processBlockComment` workflow
4. Use shared config resolution (ADR-016) for story directory lookup
5. Cache story file contents in a Map during rule execution
