# Async Catch-Clause Annotation Requirements

## Context

Async functions frequently use `try`/`catch` for error handling around `await`. The catch clause still represents a distinct execution branch and must carry traceability annotations just like non-async catch blocks.

## Requirement

**REQ-ASYNC-CATCH-INCLUDED** — Catch clauses inside async/await contexts MUST be treated the same as regular catch clauses for annotation requirements.

## Specification

1. The `require-branch-annotation` rule MUST report missing annotations on `catch` clauses inside async functions, even when the `try` body includes `await`.
2. The rule MUST accept `@story`/`@req` or `@supports` annotations on async catch clauses the same way it does for non-async catch clauses.
3. Auto-fix placement for async catch clauses MUST match non-async catch behavior (before-catch by default or inside-placement when configured).

## Examples

### Invalid: Missing catch annotation inside async function

```javascript
async function load() {
  // @story docs/stories/004.0-DEV-BRANCH-ANNOTATIONS.story.md
  // @req REQ-ASYNC-CATCH-INCLUDED
  try {
    await fetchData();
  } catch (error) {
    handleError(error);
  }
}
```

### Valid: Annotated catch clause inside async function

```javascript
async function load() {
  // @story docs/stories/004.0-DEV-BRANCH-ANNOTATIONS.story.md
  // @req REQ-ASYNC-CATCH-INCLUDED
  try {
    await fetchData();
  }
  // @story docs/stories/004.0-DEV-BRANCH-ANNOTATIONS.story.md
  // @req REQ-ASYNC-CATCH-INCLUDED
  catch (error) {
    handleError(error);
  }
}
```
