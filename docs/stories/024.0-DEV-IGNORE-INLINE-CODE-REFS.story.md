# 024.0-DEV-IGNORE-INLINE-CODE-REFS: Ignore Inline Code References in Comments

## Release Goal

**Release 0.5: Quality Foundation** - Improve plugin's annotation detection accuracy by correctly handling meta-documentation where annotation syntax is discussed rather than used.

## How This Story Contributes

This story prevents false positives when developers document the annotation syntax itself using inline code markers (backticks). Without this fix, descriptive comments like "This rule uses `@supports` annotation" or "Legacy `@story` + `@req` patterns" trigger validation errors because the plugin incorrectly treats backtick-wrapped keywords as actual annotations.

By filtering out backtick-wrapped content during comment normalization, the plugin becomes intelligent enough to distinguish between:

- **Documentation about annotations** (`` `@supports` ``, `` `@story` ``, `` `@req` ``) - should be ignored
- **Actual traceability annotations** (`@supports path/to/file.md REQ-ID`) - should be validated

This improves usability for projects that document their traceability approach in code comments, especially when explaining the preferred `@supports` annotation format.

## User Story

**Format**: So that I can document annotation syntax without triggering false positives, as a plugin developer, I want the plugin to ignore annotation keywords when they appear within inline code markers (backticks).

**INVEST Criteria Compliance**:

- **Independent**: Can be developed independently - only touches comment normalization logic
- **Negotiable**: Implementation approach (filtering in normalization vs detection) can be discussed
- **Valuable**: Prevents false positives and improves documentation quality
- **Estimable**: Clear scope - modify one normalization function and add tests
- **Small**: Single function change plus tests, completable in one iteration
- **Testable**: Clear acceptance criteria with specific test cases

- [x] **Real Annotations Detected**: Comments containing both backtick-wrapped references AND actual annotations correctly validate only the real annotations
- [x] **Multi-Line Support**: Backtick-wrapped keywords are filtered regardless of which line they appear on

## Implementation Notes (Optional)

1. Add regex pattern to detect backtick-wrapped content: `/`[^`]+`/g`
2. Replace matches with spaces (length-preserving) to maintain word boundaries
3. Apply existing normalization logic to the filtered line

**Testing Strategy**:

- Unit tests for backtick-wrapped `@story`, `@req`, `@supports` keywords
- Tests for mixed real + backtick-wrapped annotations in same comment

**Edge Cases**:

- Multiple backtick pairs on same line
- Backticks at line boundaries
