# 009.0-DEV-MAINTENANCE-TOOLS: Update Helpers for Annotation Maintenance

## Release Goal

_Core Validation: Provide essential ESLint rules that enforce @supports, @story and @req annotations on functions and code branches, with validation that referenced files exist and contain the referenced requirements, plus CLI maintenance tools for keeping annotations up-to-date_

This story provides developers with CLI helper tools and utilities to maintain traceability annotations as their codebase evolves, ensuring annotations remain accurate and up-to-date when story files are moved, renamed, or restructured.

## How This Story Contributes

As codebases grow and evolve, maintaining traceability annotations becomes an ongoing challenge. This story provides a **batch update tool** that allows developers to update all annotation references when story files are moved or renamed, eliminating the need to manually hunt through code.

Note: Detection and verification of stale references are already handled by ESLint rules (`valid-story-reference`, `valid-req-reference`) during normal linting. The maintenance tool focuses solely on the batch update operation that ESLint cannot perform.

This story initiates the "Maintain Quality" journey phase by providing the one critical tool ESLint cannot provide: bulk reference updates.

## User Story

**Format**: So that I can keep annotations accurate when story files are moved or renamed without manually editing every affected file, as a Developer, I want a batch update tool that can rename all references in one command.

**INVEST Criteria Compliance**:

- **Independent**: Can be developed using existing validation logic and file system operations
- **Negotiable**: The specific maintenance tools and their interfaces can be refined during implementation
- **Valuable**: Delivers clear value by reducing manual maintenance work as projects evolve
- **Estimable**: Scope is well-defined - implement specific maintenance utilities
- **Small**: Focused on core maintenance scenarios rather than comprehensive project management
- **Testable**: Maintenance operations can be verified through before/after file comparisons

## Requirements and Acceptance Criteria

- **REQ-MAINT-UPDATE**: Update annotation references when story files are moved or renamed via CLI commands
  - [x] **Core Functionality**: `update` command can batch-update @story and @supports references from old path to new path
  - [x] **Integration**: Works with --ignore-pattern flags to skip generated/vendor code
  - [x] **Quality Standards**: Preserves code functionality and formatting during updates
  - [x] **User Experience**: Provides clear feedback about what was changed
  - [x] **Safety**: Supports --dry-run mode to preview changes before applying

- **REQ-MAINT-BATCH**: Perform batch updates across multiple files and annotations via single CLI invocation
  - [x] **Efficiency**: Single command updates all references throughout the codebase
  - [x] **Error Handling**: Gracefully handles edge cases like missing files or malformed annotations

- **REQ-MAINT-CLI**: Implement maintenance tools as standalone CLI commands (not ESLint rules) that can be invoked manually by developers
  - [x] **Accessibility**: Available via npx traceability-maint command
  - [x] **Documentation**: Maintenance tools are documented with usage examples and best practices

- **REQ-MAINT-MANUAL-TRIGGER**: Updates are triggered by manual developer execution only, not automatically via git hooks or CI
  - [x] **Manual Execution**: Tool is designed for interactive developer use when reorganizing story files
  - [x] **No Automation**: Not intended for CI pipelines or git hooks (ESLint rules handle validation in those contexts)
  - [x] **Clear Intent**: Documentation emphasizes this is a manual refactoring aid, not an automated validator

**Note on Redundant Commands**: The CLI also includes `detect`, `verify`, and `report` commands for historical reasons, but these duplicate functionality already provided by ESLint rules during normal linting. The `update` command is the primary value-add that ESLint cannot provide.

- Leverage ESLint's SourceCode API patterns for finding and updating annotations

- Support --dry-run mode for safety
- Support --ignore-pattern flags to skip generated/vendor code
