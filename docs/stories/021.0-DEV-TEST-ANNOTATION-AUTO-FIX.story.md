# 021.0-DEV-TEST-ANNOTATION-AUTO-FIX: Auto-Fix Test Annotation Format Issues

## Release Goal

**Test Traceability** - Extend traceability validation to test files, ensuring tests are properly linked to requirements through annotations and naming conventions.

This story provides automated fixes for test annotation format issues and adds placeholder templates for missing annotations, making it easier for developers to bring test files into compliance with traceability requirements. By automating format fixes and providing clear templates, this story reduces friction in maintaining test traceability.

## How This Story Contributes

While validation (020.0) identifies test annotation issues, auto-fix capabilities help resolve format problems and provide clear starting points for missing annotations. This story completes the "Fix Issues" journey phase for test files by providing automated resolution of format violations and template placeholders that developers can fill in.

This story enables:

- Automatic correction of annotation format issues
- Consistent placeholder templates for missing annotations
- Reduced manual typing for boilerplate annotation structure
- Clear guidance on what information developers need to provide

## User Story

**Format**: So that I can quickly fix test annotation format issues and get clear templates for missing annotations, as a Developer, I want the ESLint plugin to automatically fix format violations and add placeholder templates when I run ESLint with the --fix option.

- **Independent**: Can be developed using existing auto-fix infrastructure from the Core Validation theme

## Implementation Notes

**Auto-Fix Strategies** (Safe, Non-Semantic Only):

1. **Missing `@supports` annotation**:
   - Insert file-level JSDoc comment with `@supports` template at top of file
   - Use clear placeholders requiring developer to fill in actual values
   - Template: `/** @supports path/to/story.story.md REQ-XXX-YYY */`
   - Does NOT attempt to infer story path or requirement IDs

2. **Malformed `[REQ-XXX]` prefix format**:
   - Fix spacing: `[ REQ-XXX ]` → `[REQ-XXX]`
   - Fix delimiters: `[REQ_XXX]` → `[REQ-XXX]`, `(REQ-XXX)` → `[REQ-XXX]`
   - Fix case: `[req-xxx]` → `[REQ-XXX]`
   - Only applies when REQ ID is already present, just malformed

**Explicitly OUT OF SCOPE** (Requires Semantic Knowledge):

- ❌ Adding story references to describe blocks (can't know which story)
- ❌ Adding `[REQ-XXX]` prefixes to test names (can't know which requirement)
- ❌ Inferring story paths from file location or nearby files
- ❌ Inferring requirement IDs from test behavior or file annotations
- ❌ Any fix that requires understanding test intent or requirements coverage

**Safety Considerations**:

- Never modify test implementation code, only annotations and format
- Preserve all existing formatting and indentation
- Only fix format issues where correct format is unambiguous
- Use clear placeholders (e.g., `TODO: Add story path`) when adding templates
- Avoid any fixes that might change test execution behavior

**Template Examples**:

```typescript
// Missing @supports - add template at file top with placeholders
/**
 * @supports docs/stories/XXX.X-STORY-NAME.story.md REQ-XXX-YYY REQ-XXX-ZZZ
 */

// Malformed REQ prefix - fix format only
it("[ REQ-TEST-FIX ] should work", () => {  // Before
it("[REQ-TEST-FIX] should work", () => {    // After (fixed spacing)

it("[REQ_TEST_FIX] should work", () => {    // Before
it("[REQ-TEST-FIX] should work", () => {    // After (fixed delimiter)
```

**Configuration Options**:

- `autoFixTestTemplate`: Enable/disable auto-fix for missing `@supports` template (default: true)
- `autoFixTestPrefixFormat`: Enable/disable format fixes for `[REQ-XXX]` prefixes (default: true)
- `testSupportsTemplate`: Custom template string for `@supports` placeholder

**Fixer Implementation**:

- Use ESLint's `fixer` API in `context.report()` with `fix(fixer)` callback
- Set `meta.fixable: "code"` in rule definition
- Use `fixer.insertTextBefore()` for adding templates
- Use `fixer.replaceText()` for format corrections
- Calculate proper indentation for inserted templates
- Only provide fixer when fix is guaranteed safe
