# 022.0-DEV-JSDOC-COEXISTENCE: JSDoc Tag Coexistence for Traceability Annotations

## Release Goal

**Release 1.9: Test Traceability** - Extend traceability validation to test files, ensuring tests are properly linked to requirements through annotations and naming conventions.

This story addresses a missed requirement from Release 1.8 where the annotation parser doesn't properly handle traceability annotations when they appear alongside other JSDoc tags. This ensures developers can place traceability annotations anywhere within JSDoc blocks without parser errors.

## How This Story Contributes

This story fixes a limitation in the annotation parsing logic that forces developers to place traceability annotations after all other JSDoc tags. By enabling proper coexistence with standard JSDoc tags, this story:

- Aligns with JSDoc conventions where tag order shouldn't matter
- Improves developer experience by removing arbitrary ordering constraints
- Enables more natural documentation flow where traceability can be stated upfront
- Prevents confusing parser errors that suggest invalid requirement IDs

This is essential for Release 1.9's test traceability features, as test files often have complex JSDoc structures with multiple tags that need to coexist with `@supports` annotations.

**Format**: So that I can document traceability alongside standard JSDoc tags without parser errors, as a Developer, I want traceability annotations (@story, @req, @supports) to work correctly regardless of their position relative to other JSDoc tags like @param, @returns, etc.

## Implementation Notes

**Problem Context** (from [Issue #3](https://github.com/voder-ai/eslint-plugin-traceability/issues/3)):

The current parser in `processCommentLine` and `normalizeCommentLine` functions doesn't recognize JSDoc tags as boundaries. When processing:

```javascript
/**
 * @req REQ-OPTIMIZATION
 * @param {object} data
 */
```

The parser treats everything after `@req` as the requirement ID, producing:

```
Invalid requirement ID "REQ-OPTIMIZATION@param{object}data"
```

**Root Cause**:

Parser strips whitespace including newlines when normalizing annotation values, causing it to concatenate content from different JSDoc tags.

**Solution Approach**:

1. **Update `processCommentLine` function**:
   - Detect when next line starts with JSDoc tag pattern (`@\w+`)
   - Terminate current annotation value parsing at that boundary
   - Don't treat JSDoc tag lines as continuation of previous annotation

2. **Update `normalizeCommentLine` function**:
   - Preserve line boundaries when normalizing
   - Only strip inline whitespace, not newlines that separate tags
   - Or detect tag boundaries before normalization

3. **Add boundary detection utility**:
   - Function to check if line starts with JSDoc tag
   - Pattern: `/^\s*\*?\s*@\w+/` matches JSDoc tags
   - Use to determine continuation vs new tag

**Test Cases to Add**:
