# 027.0-DEV-REDUNDANT-ANNOTATION-DETECTION: Detect and Remove Redundant Annotations

**GitHub Issue**: #6

## Release Goal

**Core Validation** - Improve code quality by detecting and removing redundant or misplaced annotations, ensuring clean, maintainable code with focused traceability coverage.

This story implements advanced validation that detects and removes redundant or misplaced annotations, ensuring clean, maintainable code by eliminating unnecessary duplication while preserving required traceability coverage.

## How This Story Contributes

This story advances the "Validate Annotations" and "Fix Issues" journey phases by identifying annotation patterns that, while technically compliant, create maintenance burden and code clutter. When developers annotate both a branch and individual statements within that branch with identical annotations, or place annotations on trivial statements that don't require separate traceability, the code becomes harder to read and maintain.

By detecting these patterns and providing auto-fix capabilities to clean them up, this story helps teams maintain clean, focused traceability annotations that add value without adding noise. This supports the Enhanced Developer Experience theme's goal of making traceability maintenance effortless by preventing annotation bloat.

## User Story

**Format**: So that I can maintain clean, readable code with focused traceability annotations without unnecessary duplication, as a Developer, I want the plugin to detect redundant annotations on statements already covered by their containing scope and provide auto-fixes to remove them.

## Requirements and Acceptance Criteria

- **REQ-SCOPE-ANALYSIS**: Analyze annotation scope to determine what code is covered by each annotation
  - [x] **Smart Scoping**: Understands annotation scope - branch annotations cover statements within the branch

- **REQ-DUPLICATION-DETECTION**: Detect when child scopes duplicate parent scope annotations
  - [x] **Branch Coverage Detection**: Detects when statements inside an annotated branch duplicate the branch's annotations

- **REQ-STATEMENT-SIGNIFICANCE**: Determine if a statement requires its own annotation or is covered by containing scope
  - [x] **Unnecessary Statement Annotations**: Identifies annotations on simple statements (return, variable assignment) that are already covered by containing scope

- **REQ-REDUNDANCY-PATTERNS**: Identify common redundancy patterns (identical story+req on branch and statement, unnecessary return annotations, etc.)

- **REQ-SAFE-REMOVAL**: Ensure auto-fix only removes truly redundant annotations without breaking coverage
  - [x] **Auto-Fix Capability**: Provides auto-fix to safely remove redundant annotations while preserving required coverage
  - [x] **Preservation of Required Annotations**: Does not flag or remove annotations on significant branches or complex logic that require separate traceability

- **REQ-CONFIGURABLE-STRICTNESS**: Allow configuration of redundancy detection (strict vs. permissive)
  - [x] **Configuration Options**: Allows teams to configure redundancy detection strictness (e.g., always require explicit annotations vs. rely on scope inheritance)

- **REQ-ERROR-MESSAGES**: Explain why an annotation is redundant and what scope already covers it
  - [x] **Clear Error Messages**: Explains why an annotation is redundant and what scope already covers it

- **REQ-DIFFERENT-REQUIREMENTS**: Preserve annotations that reference different requirements even if in same scope
  - [x] **No False Positives**: Does not flag legitimate cases where duplicate-looking annotations serve different purposes (e.g., different requirement IDs, catch blocks as separate execution paths)

- **REQ-SCOPE-INHERITANCE**: Understand that statements inherit annotations from containing branches/functions

- **REQ-CATCH-BLOCK-HANDLING**: Recognize catch blocks as distinct execution paths that warrant their own annotations, even when the same requirement is annotated in the try block. The catch block represents error handling logic - a fundamentally different code path from the success path in the try block. This applies to:
  - Catch blocks with the same `@supports` annotation as statements in the try block
  - Catch blocks implementing the same requirement via different logic (e.g., `safe = false` in catch vs. complex validation in try)
  - Multiple code paths (if/else if/catch) all contributing to the same requirement from different execution contexts
  - Test case: A try block containing annotated if/else if branches for different result types, with a catch block that also annotates the same requirement for error handling should NOT flag the catch block annotation as redundant (see issue #6 example in dry-aged-deps `evaluateVersionVulnerabilities` function)

**Redundancy Patterns to Detect**:

1. **Branch + Statement Duplication**:

```javascript
// REDUNDANT - statement annotation duplicates branch annotation
// @story docs/stories/002.0-EXAMPLE.story.md
// @req REQ-EXAMPLE
if (_mockImplementation) {
  // @story docs/stories/002.0-EXAMPLE.story.md
  // @req REQ-EXAMPLE
  return _mockImplementation(cmd, args, options, callback);
}

// CLEAN - only branch is annotated
// @story docs/stories/002.0-EXAMPLE.story.md
// @req REQ-EXAMPLE
if (_mockImplementation) {
  return _mockImplementation(cmd, args, options, callback);
}
```

2. **Multiple Annotations in Same Scope**:

```javascript
// REDUNDANT - multiple annotations on simple sequential statements
// @story docs/stories/003.0-EXAMPLE.story.md
// @req REQ-INIT
const config = loadConfig();
// @story docs/stories/003.0-EXAMPLE.story.md
// @req REQ-INIT
const validator = new Validator(config);

// CLEAN - single annotation covers related statements
// @story docs/stories/003.0-EXAMPLE.story.md
// @req REQ-INIT
const config = loadConfig();
const validator = new Validator(config);
```

3. **Trivial Statement Annotations**:

```javascript
// REDUNDANT - simple return doesn't need separate annotation
function processData(data) {
  // @story docs/stories/004.0-EXAMPLE.story.md
  // @req REQ-PROCESS
  const result = transform(data);
  // @story docs/stories/004.0-EXAMPLE.story.md
  // @req REQ-PROCESS
  return result;
}

// CLEAN - only significant logic is annotated
function processData(data) {
  // @story docs/stories/004.0-EXAMPLE.story.md
  // @req REQ-PROCESS
  const result = transform(data);
  return result;
}
```

1. **Different Requirements in Same Scope**:

```javascript
if (error) {
  logError(error);
  // @story docs/stories/005.0-EXAMPLE.story.md

```

2. **Complex Nested Logic**:

```javascript
// NOT REDUNDANT - nested branch has distinct logic
// @story docs/stories/006.0-EXAMPLE.story.md
// @req REQ-OUTER-CHECK
if (config.enabled) {
  // @story docs/stories/006.0-EXAMPLE.story.md

    validate(data);
  }

```

3. **Catch Block - Separate Execution Path** (Issue #6):

```javascript
// NOT REDUNDANT - catch block is a distinct execution path from try block
// Each annotation marks a different code path implementing the same requirement
// @supports docs/stories/007.0-EXAMPLE.story.md REQ-SAFE-OPERATION
try {
  const result = await riskyOperation();
  // @supports docs/stories/007.0-EXAMPLE.story.md REQ-SAFE-OPERATION
  if (typeof result === "number") {
    return processNumeric(result);
  }
  // @supports docs/stories/007.0-EXAMPLE.story.md REQ-SAFE-OPERATION
  else if (result && typeof result === "object") {
    return processObject(result);
  }
} catch {
  // @supports docs/stories/007.0-EXAMPLE.story.md REQ-SAFE-OPERATION
  // This is NOT redundant - catch block is a separate code path
  // The error handling path is distinct from the success paths above
  return { safe: false };
}
```

**Technical Approach**:

1. **Scope Analysis**:
   - Build annotation scope tree (function → branches → statements)
   - Track which annotations cover which AST nodes
   - Identify parent-child scope relationships

2. **Duplication Detection**:
   - Compare annotations at each scope level with parent scopes
   - Check if story file AND requirement ID match exactly
   - Flag only exact duplicates within direct parent-child relationships

3. **Significance Assessment**:
   - Identify trivial statements (simple return, single assignment)
   - Distinguish significant branches from simple statements
   - Consider statement complexity and control flow impact
   - Treat catch blocks as separate execution paths requiring their own annotations

4. **Auto-Fix Strategy**:
   - Remove annotations that exactly duplicate parent scope
   - Preserve annotations with different requirements
   - Maintain required coverage (never remove last annotation)
   - Calculate proper comment removal (including blank lines)

- Annotations on first statement vs. last statement in scope
- Comments that aren't annotations mixed with annotations
