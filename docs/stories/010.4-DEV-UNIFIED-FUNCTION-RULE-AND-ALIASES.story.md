# 010.4-DEV-UNIFIED-FUNCTION-RULE-AND-ALIASES: Unified Rule, Aliases, and @supports-First Model

## Release Goal

_Core Validation: Provide a single canonical function-level rule with backward-compatible aliases and an @supports-first annotation model_

This story formalizes the unified function-level rule `traceability/require-traceability`, its legacy aliases (`require-story-annotation` and `require-req-annotation`), and the `@supports`-first annotation model from a feature perspective. It ensures that users, documentation, and implementation all align on a single canonical rule while preserving backward compatibility for existing configurations.

## How This Story Contributes

This story strengthens the "Configure and Adopt" journey phase by:

- Giving users a clear recommendation for which rule key to use for function-level traceability.
- Ensuring legacy rule names continue to work without diverging behavior.
- Clarifying how `@supports` relates to older `@story` / `@req` annotations.

It builds on the core function-annotation story (003.0) and multi-story support (010.2, 010.3), tying together implementation, configuration, and user guidance.

## User Story

**Format**: So that I can configure function-level traceability checks without confusion, as a Developer or Team Lead, I want a single canonical rule and clear guidance on how legacy rule keys and @supports annotations behave.

**INVEST Criteria Compliance**:

- **Independent**: Builds on existing function-annotation rules and @supports implementation but focuses on configuration, wiring, and guidance.
- **Negotiable**: Details of presets and alias behavior can be tuned during implementation.
- **Valuable**: Reduces confusion for new and existing users configuring the plugin.
- **Estimable**: Scope is clear  unify rule wiring, document behavior, and align presets.
- **Small**: Can be completed within a single iteration/sprint.
- **Testable**: Behavior can be verified via rule tests and integration tests that exercise all rule keys.

## Requirements (Current Implementation or To Be Implemented)

- **REQ-ANNOTATION-REQUIRED** (extends 003.0):
  - `require-traceability` remains the unified rule that requires traceability annotations (`@story` + `@req`, or `@supports`) on all in-scope functions.
  - `require-story-annotation` and `require-req-annotation` are implemented as aliases that reference the same underlying rule logic.

- **REQ-EXPORT-PRIORITY** (extends 003.0):
  - The unified rule and its aliases continue to support configuration that prioritizes exported functions for enforcement.

- **REQ-UNIFIED-ALIAS-ENGINE**:
  - The implementation in `src/index.ts` wires `require-story-annotation` and `require-req-annotation` as aliases of `require-traceability` by:
    - Reusing the canonical rules `create` function for both aliases.
    - Merging `meta` from the canonical rule and any legacy rule modules so alias docs and options stay accurate.
  - There is a single source of truth for listener behavior: `src/rules/require-traceability.ts`.

- **REQ-SUPPORTS-FIRST-MODEL** (extends 010.2, 010.3):
  - The unified rule and its aliases accept `@supports` as satisfying story and requirement presence checks while maintaining full support for `@story` + `@req`.
  - Mixed usage (both styles in the same comment) is considered valid for presence checks; stylistic guidance (migrating to `@supports`) is handled by the `prefer-supports-annotation` rule.

- **REQ-MIGRATION-RULE-NAMING** (extends 010.3):
  - `prefer-supports-annotation` is the canonical migration rule name.
  - `prefer-implements-annotation` is retained as a deprecated alias with `meta.deprecated = true` and `meta.replacedBy = ["prefer-supports-annotation"]`.

- **REQ-PRESETS-CANONICAL-RULE**:
  - The `recommended` and `strict` presets enable `require-traceability` and may also include the legacy keys for backward compatibility, but all documentation and examples describe `require-traceability` as the primary function-level rule to configure.

- **REQ-DOCS-CONSISTENCY**:
  - README, `user-docs/api-reference.md`, `user-docs/traceability-overview.md`, and `user-docs/migration-guide.md` consistently:
    - Call out `require-traceability` as the canonical function-level rule.
    - Mark the older function-level rule keys as legacy aliases.
    - Emphasize `@supports` as the preferred annotation form for new and multi-story code, with `@story`/`@req` described as backward-compatible alternatives.
